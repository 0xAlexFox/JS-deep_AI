# Инструкции для работы с проектом

## Назначение и стек

- Учебное приложение «Сводка»: отчёт о выручке из двух источников продаж, суммы по валютам и курсы относительно USD; отдельная информационная страница источников.
- Используй JavaScript ES modules (`type: module`), Vue 3 Composition API и `<script setup>`. Сборка — Vite; зависимости и команды определены в `package.json`, версии зафиксированы в `package-lock.json`.
- Соблюдай `engines.node` из `package.json`: `^22.18.0 || >=24.12.0`. Если нужна установка зависимостей из существующего lock-файла, используй `npm ci`.
- Сохраняй учебный характер кода: понятные имена, небольшие функции, комментарии к нетривиальным расчётам. Интерфейс, документация и пояснения — на русском.
- Не добавляй TypeScript, JSX, маршрутизатор, Pinia или новые зависимости без необходимости для задачи. Папку заданий `dz/` не изменяй без прямого запроса.

- Сохраняй существующие публичные функции и их контракты, если задача не требует их изменения. При изменении поведения или настройки обновляй соответствующий раздел `README.md`.

## Правила расчёта

- Первый источник — объект с массивом `transactions`: учитываются только записи `type === 'paid'`. Второй — массив строк вида `'300 USD'`. Некорректные учитываемые данные отклоняют отчёт, а не пропускаются молча.
- Нормализуй трёхбуквенные коды валют через `normalizeCurrency`. Допускаются только конечные неотрицательные суммы с максимум двумя знаками после точки; не расширяй формат строк неявным приведением через `Number`.
- Складывай целые сотые доли отдельно для каждой валюты (`Map`), используя проверки `toCents` и `addCents`. Цены и денежные итоги должны оставаться меньше `2 ** 46` денежных единиц; одного `Number.isSafeInteger` для точного отображения сотых недостаточно.
- `rates.X` означает количество X за 1 USD. Конвертация: сумма / курс исходной валюты × курс целевой. Сохраняй точные дроби на `BigInt` и одно округление суммы валютной группы до сотой доли, половина — вверх; промежуточную сумму в USD не округляй.
- Смена целевой валюты пересчитывает исходные `totalsInCents` по сохранённому снимку курсов, без HTTP и без конвертации прежнего округлённого итога. Не изменяй исходные данные и таблицу курсов.
- Ненулевая конвертация между разными валютами требует корректных положительных курсов; нулевая сумма и перевод валюты в саму себя курса не требуют.

## Поведение экрана

- Выбор ограничен валютами учтённых продаж. При обновлении сохраняй выбранную цель, если она доступна; иначе выбирай USD, если он есть, затем первую доступную валюту. Пустой отчёт — 0 USD и отключённый выбор.
- Во время загрузки блокируй обновление и смену валюты; повторное нажатие не должно создавать вторую загрузку.
- Ошибка загрузки скрывает прежний отчёт; частичный результат не показывается. После ошибки пересчёта сохраняй исходные данные, чтобы пользователь мог выбрать другую валюту без загрузки.
- При размонтировании отменяй запросы и игнорируй запоздавшие ответы. Сохраняй передачу `AbortSignal` и тайм-ауты, включая чтение тела ответа.
- Дата курсов принадлежит поставщику; при отсутствии корректных метаданных показывай отсутствие даты, а не текущее время. Форматирование сумм и дат держи в `src/utils/format.js`.
- Сохраняй доступность: подписи полей, `aria-busy`, уведомления о состоянии, фокус на заголовке ошибки, управление с клавиатуры и поддержку `prefers-reduced-motion`. Длинные суммы и таблица должны оставаться читаемыми на телефоне.
- Выводи ошибки как текст через интерполяцию Vue; не используй `v-html` для внешних данных.

## Ключ и локальный сервер

- `FINANCE_API_KEY` читается только в Node.js из окружения или корневого `.env.local`; окружение имеет приоритет. Не перезаписывай существующий `.env.local`. Если файла нет, используй `.env.example` как образец.
- Не добавляй секрет в `src/`, `VITE_*`, `define`, клиентские запросы, тестовые снимки, сообщения об ошибках или логи. В тестах используй вымышленные ключи.
- Браузер вызывает `/api/finance1` и `/api/finance2` без ключа. Только `server/finance-proxy.js` добавляет `x-api-key` к двум фиксированным адресам из `UPSTREAM_URLS`; курсы загружаются отдельно без этого ключа.
- Сохраняй ограничения прокси: GET, точный разрешённый путь без query-параметров, локальные Host/Origin, запрет cross-site запросов и редиректов. Не пересылай клиенту тела и заголовки ошибок внешнего API.
- Dev/preview слушают `127.0.0.1` и требуют ключ; сборка ключа не требует. Не ослабляй запреты доступа Vite к `.env*`, `.local/`, серверным модулям и служебным конфигурациям.
- Один `dist/` на статическом хостинге не обеспечивает работу `/api/finance*`. Публичное размещение требует отдельного backend/serverless и контроля доступа; Vite preview служит локальной проверке.

## Проверки

- Сначала изучай затронутый слой и его тесты, ищи через `rg`. Не запускай внешние API с настоящим ключом для автоматических проверок.
- Для точечной проверки Node.js передавай нужные файлы: `node --test --test-concurrency=1 tests/revenue.test.js tests/currency.test.js`. Сетевой слой проверяется в `tests/api.test.js`, состояние и сборка отчёта — в `tests/dashboard.test.js`, прокси и настройки — в `tests/server.test.js`.
- `npm run test:unit` запускает все `tests/*.test.js` через Node.js. Серверные тесты поднимают локальный HTTP-сервер на свободном порту; внешний fetch подменён.
- `npm run test:components` запускает Vitest, Vue Test Utils и jsdom для `tests/components/`. Отдельный `vitest.config.js` изолирует эти тесты от Vite-конфигурации с ключом. Сохраняй один worker и `fileParallelism: false`.
- Для изменения поведения добавляй проверки соответствующих сценариев, используя существующие `fetchImpl`, `loadReport` и `logger` для подмены зависимостей. Не подменяй сам проверяемый расчёт или компонент.
- После изменений кода выполни один итоговый `npm test`, затем `npm run build`. Запускай тяжёлые проверки последовательно; повторяй только затронутые проверки после исправлений или при неустранённом риске.
- Для изменений только инструкций и документации достаточно сверки путей, команд и `git diff --check`; сборка и тесты приложения не нужны.
- При изменениях интерфейса проверь затронутые состояния и узкий экран. `npm run dev` — разработка, `npm run preview` — просмотр уже собранного `dist/`; порт задаётся через `PORT` (по умолчанию 5173).
- Логи, отчёты и состояние длительных проверок сохраняй по точным путям из раздела «Локальные служебные файлы»; в итоговом ответе указывай команды, результаты и реальные ограничения.

## Локальные служебные файлы

- Все служебные пути ниже относительны к корню этого проекта. Логи команд сохраняй в `.local/<задача>-<проверка>.log`, отдельные отчёты/результаты — в `.local/<задача>-results/`; готовый `dist/` остаётся результатом сборки в своём штатном месте.
- Реестр длительных проверок — `.local/checks.md` (создавай при первой такой проверке). До запуска запиши задачу, точную команду, пути журнала/отчёта и ожидаемую проверку; после запуска — PID/ID сессии, после завершения — результат и следующее действие. Не включай секреты.
- После обрыва сначала сверь реестр с файлами, журналами и фактической командой процесса: PID может быть переиспользован. Не объявляй отсутствие процесса успехом и не повторяй запуск вслепую. Обнови `.local/checks.md` установленным состоянием.
- Перед записью создай папку при необходимости. Не создавай служебные `*.local` в корне проекта.
- Исключение: `.env.local` с настоящим ключом остаётся в корне; публичный образец — `.env.example` рядом с ним.
- Не публикуй `.local/` и не выводи секреты в консоль. Папка исключена из Git и закрыта для HTTP-доступа.
- Не удаляй прежние результаты проверок при наведении порядка; сохраняй их имена и содержимое.
