# Контракт и границы аудита

Источник истины о текущем клиенте: `src/domain/revenue.js`, `money.js`, `currency.js`, `src/services/api.js`. Это ожидания frontend, а не опубликованная OpenAPI-спецификация backend. При изменении приложения пересмотри правила аудитора.

| Источник | Ожидаемый ответ | Что учитывать |
| --- | --- | --- |
| finance1 | Объект с массивом `transactions` | Каждая запись - объект. В расчёт входят только точные `type === 'paid'`. Сумма - число, валюта - строка. |
| finance2 | Массив строк вроде `300 USD` | Все записи считаются оплаченными. Только обычная десятичная запись, максимум 2 знака; код отдельным словом. |
| rates | `result: success`, `base_code: USD`, объект `rates`, `rates.USD === 1` | Для ненулевого обмена нужны конечные положительные курсы. Дата принадлежит поставщику. |

## Смысл замечаний

- Регистр и пробелы - неоднородность: клиент умеет нормализовать коды, но это полезно исправить на сервере. Смешанные варианты группируются отдельно.
- Неизвестный трёхбуквенный код сверяется с текущим [List One SIX / ISO 4217](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html). Отсутствующий код может быть историческим, внутренним или ошибочным. Не называй его безусловно «несуществующим» без дополнительного подтверждения.
- `XXX`, `XTS`, металлы и расчётные единицы существуют в ISO, но требуют отдельного соглашения для обычных платежей. `Intl.DisplayNames` не является проверкой существования кода.
- Отсутствие кода в `rates` - вопрос поддержки конвертации, не существования валюты. При одной валюте обмен может вообще не потребоваться.
- Максимум два знака - договорённость этого клиента. Трёхзначная дробь для некоторых валют может быть допустимой по ISO, но несовместимой с приложением. Возвраты также требуют отдельного контракта.
- Деньги и группы проверяются существующими `toCents`/`addCents`. Предел меньше `2 ** 46` денежных единиц сохраняется; не переписывай денежный алгоритм ради аудита.
- Полный enum статусов не известен: не объявляй произвольный неоплаченный статус ошибкой. `Paid` или ` paid ` выделяй: текущий клиент не засчитает их как `paid`.
- Одинаковые суммы или одинаковые строки не доказывают дубли. Проверяется только повтор ID, если он присутствует, с рекомендацией разобраться. Значение ID не выводится.

## Снимок для offline-режима

```json
{
  "mode": "offline",
  "finance1": {"ok": true, "status": 200, "data": {"transactions": []}},
  "finance2": {"ok": true, "status": 200, "data": []},
  "rates": {"ok": true, "status": 200, "data": {
    "result": "success", "base_code": "USD", "rates": {"USD": 1},
    "time_last_update_utc": "2026-01-01T00:00:00Z"
  }}
}
```

Недоступный источник: `{"ok": false, "status": 503}`. Не подставляй вместо него пустой успешный массив. Чужой снимок может содержать приватные данные: не помещай его в fixtures или Git.

## Формат результатов

`report.json` содержит время, режим, полноту, метаданные источников, справочник, группы замечаний и максимум 5 безопасных примеров на группу. `report.md` и необязательный PDF строятся из этого результата. Поля клиентов, полные записи и секретные заголовки не сохраняются.

Время проверки - UTC, отображение - Europe/Moscow. ISO-справочник старше 30 дней отмечается как ограничение. Порог устаревания ежедневных курсов в этом аудите - 72 часа, не универсальная норма рынка.
