# Аудит финансовых API

Создай воспроизводимый отчёт с наблюдаемыми проблемами, их влиянием и рекомендациями. Действуй в корне этого репозитория. Прочитай [контракт и правила выводов](references/contract.md).

## Режимы

- **Текущие ответы:** пользователь просит проверить работающие API. Один явно запущенный аудит читает два разрешённых endpoint и публичный сервис курсов. Это диагностическая операция по запросу владельца, не автотест приложения.
- **Локальный снимок:** пользователь передал файл. Используй `--input`; не обращайся к сети и укажи время/границы снимка. Схема входа описана в справочнике.
- Автотесты работают только с вымышленными данными и подменённым `fetchImpl`. Сами по себе создание/загрузка skill и `npm test` не разрешают живой запрос.

## Выполнение

1. Проверь доступность `.env.local`/окружения через `server/config.js`, не печатая значения. Не меняй ключ, прокси, данные и приложение.
2. Проверь дату `assets/iso4217.json`. Для живого аудита при возрасте более 30 дней обнови публичный справочник:

   ```bash
   python3 .agents/skills/finance-api-audit/scripts/refresh-currencies.py
   ```

   Если загрузка не удалась, не отключай TLS. Укажи ограничение; старый список не доказывает актуальность кодов. Скрипт принимает `--input` для официального XML, полученного другим доступным способом с проверкой TLS.
3. Запусти нужный режим. Результат автоматически получает новую папку внутри `.local/finance-api-audit-results/`:

   ```bash
   node .agents/skills/finance-api-audit/scripts/audit.mjs --live
   # Либо:
   node .agents/skills/finance-api-audit/scripts/audit.mjs --input /абсолютный/путь/snapshot.json
   ```

   Код 0 подтверждает создание отчёта, не здоровье сервера. Прочитай `report.json` и `report.md`, проверь полноту, числа и примеры. Не объявляй недоступный источник корректным. Не повторяй запросы автоматически; при сетевом сбое сохрани частичный отчёт и назови ограничение.
4. Убедись, что отчёт различает дефекты формата, несовместимость с контрактом клиента и вопросы к контракту. Не исправляй и не переименовывай валюты за backend.
5. При запросе PDF создай его из того же `report.json`:

   На macOS доступен рендерер на системных CoreText/CoreGraphics без сторонних зависимостей:

   ```bash
   swiftc -j2 -module-cache-path .local/finance-api-audit-module-cache .agents/skills/finance-api-audit/scripts/render-pdf-macos.swift -o .local/finance-api-audit-render-pdf
   .local/finance-api-audit-render-pdf /путь/к/report.json
   ```

   Он создаёт PDF и PNG всех страниц в `pdf-preview/` рядом с отчётом. На другой ОС используй доступный PDF-skill или проверенный рендерер. Для визуальной проверки используй доступный PDF-skill/рендерер и просмотри все страницы. Не выдавай MD за созданный PDF. Если PDF-инструменты недоступны, передай Markdown и точное ограничение.
6. В ответе дай ссылки на готовые файлы, число групп замечаний, основные подтверждённые примеры и ограничения. Не отправляй отчёт другим людям без отдельного поручения.

## Сохранность и доказательства

- Ключ берётся только в Node.js и отправляется только двум фиксированным адресам из `UPSTREAM_URLS`. Он не передаётся провайдеру курсов, справочнику или в аргументах команд. Редиректы запрещены.
- Не сохраняй сырые ответы по умолчанию. В отчёте допустимы JSON-путь и минимальный пример некорректного поля; ID и поля клиентов не включай. Проверь итог на наличие секрета перед передачей.
- Отчёты, PDF и журналы остаются в `.local/`, вне Git и HTTP-доступа. Не перезаписывай прежние отчёты. Учитывай, что даже обезличенный отчёт может содержать непубличные сведения о данных.
- Не используй число найденных проблем как доказательство исправности API за другие даты. Отчёт отражает один снимок, без скрытого тестирования нагрузкой или изменения серверных записей.

Для проверки самого инструмента: `node --test --test-concurrency=1 tests/finance-api-audit.test.js`. Эта команда не использует реальные ключи и не делает внешних запросов.
