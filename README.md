# Сводка — выручка из двух источников

Учебный проект на **Vue 3 + JavaScript + Vite**, без TypeScript.
Получает продажи из двух API, показывает общую выручку, отдельные суммы по валютам
и курсы. Папка заданий `dz/` сохранена без изменений.

## Запуск

Требуется Node.js **22.18+ или 24.12+** (рекомендуется актуальная Node.js 24).
Для `.vue`-файлов в VS Code рекомендуется расширение **Vue (Official)**.

```bash
npm install
```

Если настроек ещё нет, создай локальную копию образца:

```bash
cp .env.example .env.local
```

Укажи в `.env.local` свой `FINANCE_API_KEY`. Уже заполненный файл заменять не нужно.
Настоящий ключ остаётся только в этом файле, исключённом из Git.

```bash
npm run dev
```

Открой `http://127.0.0.1:5173` (или порт из `.env.local`). Не открывай
`index.html` напрямую через `file://`.

## Архитектура

```text
src/
  main.js                     # Монтирует Vue и подключает стили
  App.vue                     # Собирает экран и управляет его жизненным циклом
  components/                 # Представление: props вниз, события вверх
    DashboardHeader.vue       # Выбор целевой валюты и обновление
    ReportSummary.vue         # Общая выручка
    CurrencyBreakdown.vue     # Исходные суммы по валютам
    ExchangeRates.vue         # Курсы и время их обновления
    ReportLoading.vue         # Состояние загрузки
    ReportError.vue           # Ошибка, подробности и повторная попытка
  composables/
    useRevenueReport.js       # Реактивное состояние и действия пользователя
  services/
    api.js                    # HTTP, JSON, тайм-ауты и проверка ответа курсов
    reports.js                # Получение источников и подготовка отчёта
  domain/
    money.js                  # Проверка сумм, нормализация валют, целые центы
    currency.js               # Конвертация и кросс-курсы
    revenue.js                # Разбор продаж, группировка и общий итог
  utils/format.js             # Русское форматирование сумм, валют и времени
  config.js                   # Публичные настройки без секретов
  style.css                   # Общие стили и адаптация к телефону
server/
  config.js                   # Читает локальный ключ только в Node.js
  finance-proxy.js            # Передаёт ключ двум разрешённым API
```

Компоненты используют Composition API и `<script setup>` на JavaScript.
Vue обновляет шаблоны из реактивного состояния. Компоненты получают данные через
`props`, а действия передают родителю через события. Проверки `props` описаны
обычными JavaScript-объектами. Ответы API проверяются во время выполнения.
Денежные функции не зависят от Vue, DOM и сети.
Маршрутизатор, Pinia, JSX и TypeScript не подключены: экран один, его состояние
принадлежит `App.vue`. Vitest, Vue Test Utils и jsdom используются только для тестов.

## Поведение

- Из первого источника учитываются только транзакции `paid`, из второго — все
  корректные строки продаж. Коды `usd`, `USD`, `eur` нормализуются.
- Во время загрузки кнопка обновления и выбор валюты заблокированы; двойной клик
  не запускает вторую загрузку.
- Цель выбирается из валют учтённых продаж: USD, если он есть, иначе первая
  доступная валюта. Пустой отчёт показывает 0 USD с отключённым переключателем.
- Смена цели использует исходные целые суммы и тот же снимок курсов из памяти,
  без повторных запросов и конвертации уже округлённого общего итога.
- Обновление сохраняет выбранную валюту, если она осталась в новых продажах.
- При ошибке загрузки старый отчёт скрывается, частичный итог не показывается.
  Есть подробности и повторная попытка. После ошибки пересчёта можно выбрать
  другую валюту без новой загрузки данных.
- При закрытии компонента запросы отменяются, запоздавшие ответы игнорируются.
- В консоль выводятся результат расчёта и ошибки. Тесты не запускаются в браузере.

## Курсы и округление

Источник: [ExchangeRate-API](https://www.exchangerate-api.com/docs/free),
`https://open.er-api.com/v6/latest/USD`. Ключ не требуется; курсы обновляются
ежедневно. Время обновления берётся из ответа поставщика и показывается в МСК.
Если метаданные отсутствуют, интерфейс сообщает об этом, не подставляя время
открытия страницы.

`rates.EUR` — количество евро за 1 USD. Формула:
**сумма / курс исходной валюты к USD × курс целевой валюты к USD**.
Например, при EUR = 0.8 сумма 100 EUR превращается в 125 USD.
Это пример формулы, а не актуальная котировка.

Сначала складываются целые сотые доли каждой исходной валюты. При конвертации
курсы представлены точными десятичными дробями на `BigInt`; итог группы округляется
один раз, половина сотой доли — вверх. Промежуточный результат в USD не округляется.
Затем складываются группы целевой валюты.

Ограничения учебного решения: неотрицательные суммы, максимум два знака после
точки. Цены и итог каждой валюты должны быть меньше `2**46` денежных единиц
(70 368 744 177 664), чтобы `Number` сохранял сотые доли при отображении.
Возвраты, исторические курсы, фильтр периода и особые дробные разряды отдельных
валют пока не реализованы. Отсутствие корректного курса ненулевой суммы — ошибка;
нулевые продажи не требуют курса.

## Проверка и сборка

```bash
npm test
npm run build
npm run preview
```

`npm test` последовательно запускает проверки расчётов, API, реактивного состояния
и серверного обработчика через Node.js, затем компонентные тесты Vitest в jsdom.
Используется один worker, параллельный запуск файлов отключён. Внешние API
подменяются: тесты не зависят от интернета и настоящего ключа.
Отдельные команды: `npm run test:unit` и `npm run test:components`.
`npm run build` собирает приложение в `dist/`; ключ для сборки не требуется.
Dev и preview без ключа завершаются с инструкцией по настройке.

## Безопасность и публикация

Браузер обращается к локальным `/api/finance1` и `/api/finance2` без ключа.
Серверный обработчик Vite добавляет `x-api-key` только к двум разрешённым API.
Секрет хранится в корневом `.env.local` без префикса `VITE_`; публичный образец
`.env.example` остаётся в Git. Ключ не попадает в клиентские настройки и сборку.
`.env*`, `.local/`, серверные модули и служебные конфигурации закрыты от прямого
доступа через dev-сервер. Сервер слушает `127.0.0.1`; посторонние Host/Origin
и редиректы API запрещены. Сообщения об ошибках выводятся текстом, без `v-html`.

Это схема для локальной разработки и сдачи работы. Для публичного размещения
нужен backend/serverless с ключом в настройках хостинга и проверкой доступа
пользователей. Загрузка одного `dist/` на статический хостинг не обеспечит работу
локального API. Vite preview не предназначен для промышленного хостинга.
Перенос ключа не удаляет его из старых коммитов; настоящий скомпрометированный
секрет нужно отозвать и заменить у поставщика.

## Локальные служебные файлы

Логи тестов, сборок и временных серверов хранятся в `.local/`, исключённой из Git.
Прежние результаты проверок не удаляются. Корневой `.env.local` — действующие
настройки с ключом, а не технический лог; он остаётся на месте.
