# Дневная выручка из двух серверов

Решение заданий `dz/0311.md` и `dz/0511.md`. Задание `dz/3010.md` не изменялось.
Фиксированные данные старого `script.js` заменены загрузкой из API.
В браузере подключён только `src/main.js`; общие функции вынесены в модули.

## Запуск

```bash
npm install
cp .env.example .env.local
```

Открой `.env.local` и заполни `FINANCE_API_KEY` своим ключом. Значение остаётся
только у тебя: файл исключён из Git, а `.env.example` содержит пустой образец.
Если `.env.local` уже заполнен, повторно копировать образец не нужно.

```bash
npm run dev
```

Требуется Node.js 20.19+ или 22.12+ (подойдёт установленная Node.js 24).
Открой `http://127.0.0.1:5173`. На странице появится отчёт; результат также
сохраняется в консоли разработчика браузера.
Если изменил `PORT` в `.env.local`, используй этот порт. Если ключ не заполнен,
dev/preview не запустятся и выведут понятную инструкцию по настройке.
После загрузки обоих источников и курсов результат также появится в консоли.
По умолчанию выбирается USD, если он присутствует среди оплаченных продаж:

```text
Выручка за день: { total: ..., currency: 'USD' }
```

Сумма зависит от ответов серверов и загруженного курса, поэтому она не зашита в код.
При неудачном запросе или некорректных данных страница показывает ошибку и кнопку
повторной попытки. Прежний отчёт скрывается, частичный итог не выводится.
Проверки не запускаются при открытии страницы и не засоряют её консоль.
Не открывай `index.html` напрямую через `file://`: проект использует Vite и ES-модули.

## Порядок работы

1. `src/main.js` соединяет интерфейс и загрузку. В `src/dashboard.js` функция
   `loadRevenueReport` готовит данные, а контроллер управляет загрузкой, успехом
   и ошибкой. `src/view.js` обновляет DOM, не выполняя сетевых запросов.
   `await` ждёт результат, `Promise.all` объединяет независимые запросы.
2. `src/config.js` хранит только публичные настройки: локальные адреса API, адрес курсов
   и тайм-аут. Секретных значений в клиентском коде нет.
3. `src/api.js` получает продажи с локальных `/api/finance1` и `/api/finance2` без ключа.
   Серверный модуль `server/finance-proxy.js` добавляет `x-api-key` к запросам на учебный
   сервер. `server/config.js` читает ключ из `.env.local` только в Node.js.
   Vite подключает этот обработчик через `vite.config.js`, поэтому достаточно одной
   команды запуска. Курсы браузер получает отдельно из открытого сервиса без ключа.
4. `src/revenue.js` учитывает только `paid` первого источника и все продажи второго.
   Коды `usd`, `USD`, `eur` приводятся к заглавным буквам. Суммы сначала группируются
   по валютам, поэтому доллары и евро не складываются напрямую.
5. `src/money.js` проверяет суммы и переводит их в целые сотые доли валюты.
   Так сложение `0.10` и `0.20` даёт ровно `0.30`.
6. `src/currency.js` переводит каждую валютную группу в выбранную целевую валюту,
   затем `revenue.js` складывает результаты и возвращает `{ total, currency }`.

Для части 3 доступна функция `calculateRevenueByCurrency(source1, source2)`:
она возвращает отдельные итоги, например `{ USD: 3020, EUR: 1910 }`.
Для части 4 используется `calculateDailyRevenue(source1, source2, rates)`;
необязательный четвёртый аргумент задаёт целевую валюту, например `'EUR'`.
Комментарии рядом с кодом объясняют важные действия и синтаксис.

## Интерфейс — задание 05.11

На странице реализованы все четыре пункта:

1. Общая выручка в выбранной валюте после конвертации — большая карточка в начале отчёта.
2. Отдельные карточки с исходными суммами для каждой валюты до конвертации.
   Список строится из ответа сервера, а не ограничен USD и EUR.
3. Экран ошибки с повторной попыткой и раскрывающимися подробностями.
   Во время загрузки отображается заглушка, а кнопка обновления заблокирована.
4. Таблица курсов для валют отчёта с обоими направлениями обмена и датой,
   которую передал поставщик. Дата показывается по московскому времени.

Кнопка «Обновить данные» заново получает продажи и курсы. Двойной клик не запускает
два параллельных обновления. При отсутствии продаж отображается 0 USD и пояснение.
Переключатель «Целевая валюта» формируется из валют оплаченных продаж обоих источников.
Неоплаченные транзакции не добавляют варианты. Если USD отсутствует, выбирается первая
доступная валюта; при отсутствии продаж переключатель заблокирован.

Смена цели пересчитывает сохранённые исходные группы в целых сотых долях без запросов
к серверам. Меняются итог, подписи и оба направления курсов; исходные суммы остаются
в своих валютах. Повторные переключения не конвертируют уже округлённый общий итог.
После обновления данных выбор сохраняется, если такая валюта всё ещё присутствует;
иначе используется USD или первая доступная валюта.
На телефоне карточки перестраиваются в один столбец, таблица прокручивается отдельно.
Ошибки и состояния загрузки доступны скринридеру; кнопки работают с клавиатуры.
Данные серверов вставляются через `textContent`, без выполнения полученного HTML.

Для ручной проверки ошибки открой `npm run preview` после сборки, затем останови
этот сервер и нажми «Обновить данные» в уже открытой странице. Появится ошибка.
Запусти preview снова и нажми «Попробовать ещё раз» — отчёт восстановится.

## Курсы и округление

Используется [открытый ExchangeRate-API](https://www.exchangerate-api.com/docs/free):
`https://open.er-api.com/v6/latest/USD`. Ключ не нужен, курсы обновляются ежедневно,
это не биржевые котировки в реальном времени. На странице указана ссылка на поставщика.
Курсы загружаются один раз при запуске страницы и общие для всего расчёта.

База загружаемой таблицы всегда USD, независимо от выбора цели в интерфейсе.
`rates.EUR` показывает, сколько евро соответствует **одному доллару**.
Поэтому для перевода евро в доллары сумму нужно **делить** на курс.
Учебный пример: при `rates.EUR = 0.8`, `300 EUR / 0.8 = 375 USD`.
Это иллюстрация формулы, а не текущий курс.

Общая формула: сумма / курс исходной валюты к USD × курс целевой валюты к USD.
Например, при EUR=0.8 и GBP=0.5, 100 EUR превратятся в 62.50 GBP.

Сначала складываются продажи одной валюты, затем её общий итог конвертируется
и округляется до двух знаков целевой валюты. Промежуточный результат в USD не округляется.
Курсы представлены точными десятичными дробями на BigInt, поэтому половина сотой доли
не превращается из-за погрешности Number в значение чуть ниже половины.
После этого складываются итоги в выбранной валюте.
Неоплаченные и нулевые продажи не требуют курса. Для ненулевой суммы отсутствие
положительного конечного курса считается ошибкой: пропускать такую сумму нельзя.

Ограничения учебного решения: неотрицательные исходные суммы с максимум двумя
знаками после точки. Цены и итог в каждой валюте должны быть меньше `2**46`
денежных единиц (70 368 744 177 664): выше этой границы Number уже не сохраняет
сотые доли во всех случаях. Такие суммы отклоняются, даже если количество центов
ещё помещается в безопасное целое число.
Возвраты и особые правила дробных разрядов отдельных валют не реализованы.

## Проверка

```bash
npm test
npm run build
```

Тесты находятся в `tests/` и запускаются последовательно. Они проверяют расчёт,
направление конвертации, округление, форматы обоих источников, ошибки HTTP,
неверный JSON, тайм-ауты, локальные настройки и передачу ключа только с сервера.
`tests/dashboard.test.js` проверяет подготовку отчёта, дату курсов, переходы
между загрузкой, результатом и ошибкой, повторную попытку и блокировку дубликатов.
Дополнительно проверяются выбор и сохранение целевой валюты, пересчёт без запросов,
исчезновение валют из данных; `tests/currency.test.js` проверяет кросс-курсы и округление.
В тестах курсы фиксированы, чтобы результат не зависел от даты или интернета.
Vite собирает приложение для браузера в `dist/`. Для локального просмотра сборки
запусти `npm run preview`: он тоже использует серверный обработчик и `.env.local`.

## Где находится ключ

Настоящий ключ хранится в `.env.local` под именем `FINANCE_API_KEY`, без префикса
`VITE_`. Публичный образец `.env.example` отслеживается Git, настоящий файл — нет.
`parseEnv` читает настройки в отдельный объект, не изменяя глобальное окружение.
При изменении ключа перезапусти `npm run dev` или `npm run preview`.

Браузер отправляет запрос без секрета на локальный API. Обработчик в Node.js
добавляет ключ и запрашивает один из двух фиксированных адресов преподавателя.
Ключ не включается в клиентскую сборку, заголовки ответа или сообщения ошибок.
Запросы с посторонним Host/Origin и редиректы внешнего API запрещены.
Локальный сервер слушает только `127.0.0.1`, доступ из сети не включён.

Это схема для локальной разработки и проверки домашней работы. Для публикации
сайта потребуется отдельный backend/serverless с секретом в настройках хостинга:
простая загрузка `dist/` на статический хостинг не обеспечит работу локального API.
Vite preview не предназначен для промышленного хостинга.

Перенос ключа не удаляет его из старых коммитов. Для настоящего скомпрометированного
секрета требуется отзыв/замена у поставщика; переписывание Git не отменяет утечку.

## Локальные служебные файлы

Все логи проверок, сборок и временных серверов хранятся в `.local/`, чтобы не
засорять корень проекта. Например, вывод тестов можно сохранить командой:

```bash
mkdir -p .local
npm test > .local/.test-results.local 2>&1
```

Большинство файлов `*.local` здесь — технические результаты предыдущих проверок.
Отдельно в корне остаётся `.env.local`: это действующие настройки с ключом,
а не лог. Он нужен для запуска и тоже исключён из Git; не удаляй его при очистке логов.
Папка целиком исключена из Git и закрыта от HTTP-доступа в режиме разработки.
Постоянное правило размещения таких файлов записано в `AGENTS.md`.
